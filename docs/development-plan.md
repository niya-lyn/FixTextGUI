# FixText 第一版功能范围与开发排期

**本文档回答一个问题：第一版（V1）做什么、不做什么、按什么顺序做。**

范围 = 修订后首屏 6 入口 + P0 易用性五项底线；架构 = Python 统一界面重写 + Go 引擎保留为内置替换后端（随软件分发）；排期口径 = 里程碑 + 依赖 + 可委托任务，**不估工时**，全部任务以「目标 / 范围 / 验收标准 / 依赖 / 产出物」形态拆解，完成即验收。

编制依据为四份已完成的前置评估报告（产品化可行性、综合可行性调研、技术可行性、P0 前置验证，均为内部材料）。本文不重复其论证，只引用结论并做范围决策。

## 一、定位与编制依据

本文档是 V1 的**执行规划**：锁定 V1 功能范围与逐项验收标准、架构基线、里程碑与任务拆解、关键依赖与风险、发布判定条件。仅规划，不修改任何代码；可行性论证与技术细节以前置评估报告为准，本文引用不重复。

不估算工时。本文的排期部分不含人日估算与日历排期，采用「里程碑 + 进入 / 退出条件 + 可独立承接的任务」形态：每项任务自带目标、范围、验收标准、依赖与产出物，完成即验收。原技术报告中的人日区间仅作历史参考，不构成 V1 执行依据。

## 二、V1 功能范围

### 2.1 范围总原则

V1 只做一条主干闭环：让 B 层目标用户（自出版作者 / 网文写手）**无需阅读文档**，独立完成「导入一本书 → 一键校正 → 检查问题 → 导出干净文件 →（必要时）安全维护词库」全流程。范围 = 首屏 6 入口 + P0 易用性五项底线；首屏之外的功能一律进排除项清单（2.5），去向明确。

### 2.2 首屏 6 入口：功能点与验收标准

| 入口 | 功能点 | 验收标准（V1） |
|-|-|-|
| **① 导入书籍** | 拖放 / 选择 TXT、EPUB 文件；自动识别编码（GBK 等自动转 UTF-8）；EPUB 自动合并为工作文本（导入时询问「直接处理还是先转 TXT」）；导入即复制到内部工作区，不触碰原文件路径 | ① 拖放与文件选择双通道可用；② 常见编码（UTF-8 / GBK / GB18030）零配置正确识别，转换时以人话提示；③ EPUB 导入无概念暴露（不出现 spine / OPF 等术语）；④ 原文件字节不被修改（对照校验） |
| **② 一键校正** | 默认配置一键执行「排版规范化 + 词库替换 + 标点标准化」；不询问词库组合；排版项作为可选项折叠呈现；执行中可视化进度 + 可取消 | ① 无任何命令行窗口出现；② 进度条带步骤说明且可中途取消，取消后不留半成品状态；③ 20MB 级书籍在 Go 后端下 10 秒级完成（指示性，以真实语料复测为准）；④ 处理前自动快照，可恢复到处理前 |
| **③ 检查问题** | 引号配对检查与交互式修复（迁移现有 GUI 版能力）；问题清单列出位置，点击定位到上下文；一键修复 | ① 检查结果与既有基线一致（用回归基线集对照）；② 每条问题可定位、可单独处理、可批量修复；③ 修复动作可撤销 |
| **④ 词库管理** | 一级入口，细化见 2.4（新增 / 查重 / 检索 / 删除 / 合并五操作 GUI 化 + 自动生成书籍专有词库 + 五条安全底线） | 见 2.4 逐项验收标准（V1 验收项，缺一不发布） |
| **⑤ 导出结果** | 导出干净 TXT；EPUB 输入自动拆分还原为 EPUB；替换报告以文件形式留存（CSV / 文本），不在 V1 做 GUI 呈现 | ① 导出文件可直接导入主流阅读器（不做格式宣称，以内测设备验证为准）；② EPUB 还原后可正常打开阅读；③ 每次导出自动附替换统计（命中数、涉及词库） |
| **⑥ 历史记录** | 任务列表：每次校正记录书名、时间、替换数；从历史恢复到任一快照；重新导出历史结果 | ① 历史记录跨会话保留（重启不丢）；② 任一快照可完整恢复现场并重新导出；③ 清理历史为显式操作且需二次确认 |

### 2.3 P0 易用性五项底线（V1 验收项，缺一不发布）

| 底线项 | 内容 | 验收标准（V1） |
|-|-|-|
| **免安装分发** | 绿色文件夹 + zip 分发（PyInstaller --onedir），解压后双击主 exe 即用，不暴露 PHP / Go / Python 依赖 | 干净 Windows 10/11 64 位环境解压后双击主 exe 即用，全程无技术名词；Go 引擎随包就位（见 3.2） |
| **只读保护** | 导入即复制到工作区，绝不直接修改用户原始文件；破坏性操作需二次确认 | 全流程结束后原文件字节与导入前完全一致（自动化校验）；产品内不存在无确认的删除类入口 |
| **人话错误提示** | 错误转为用户语言（如「这本书的编码是 GBK，我们已自动转为 UTF-8」），不出现堆栈跟踪 | 内测全程零堆栈 / 命令行报错露出；每类错误有明确下一步指引 |
| **可视化进度** | 带步骤说明的进度条 + 预计剩余时间，可取消 | 任何超过 3 秒的操作都有进度反馈；取消即时生效且不留脏状态 |
| **首次使用向导** | 三步演示「导入 → 处理 → 导出」，附带示例书 | 新用户 2 分钟内走完向导并产出第一个结果；向导可跳过、可重看 |


### 2.4 词库管理（核心模块）细化

词库管理从高级功能上调为首屏一级入口：词库是校正质量的根基，用户遇到「替换错了 / 没替换到 / 想加自定义词」时若无路可走，易用性闭环不成立。

#### 2.4.1 词条操作 GUI 化（五操作）

| 操作 | 功能点 | 验收标准（V1） |
|-|-|-|
| **检索** | 全库关键词检索（词 / 值双向），结果列表呈现，支持定位与编辑 | 30 万条规则量级下检索秒级返回；检索结果可直接编辑保存 |
| **查重** | 同词不同值、同值不同词的冲突检测；结果按影响分组 | 查重结果先给预览清单，确认后才执行处理；处理动作可撤销 |
| **删除** | 单条与批量删除；删除前展示影响范围（该词条命中过哪些书） | 删除必须经过预览确认；误删可撤销（见五条底线） |
| **合并** | 冲突词条合并为目标词条，来源与去向可追溯 | 合并前给预览清单（改哪些、删哪些、留哪个）；合并可撤销 |
| **新增** | 在词库管理界面手动添加词条（词 / 角色名 + 类型与注音、替换值等字段），写入自定义词库分级存储（见 2.4.3），加入前自动查重并对同词 / 同值冲突给出提示 | 新增词条进入自定义词库且与内置词库分开管理；冲突提示正确触发；新增操作可撤销（同五条底线） |

#### 2.4.2 自动生成书籍专有词库（纳入 V1）

处理完一本书后提示「把本书专有词条加入词库」，作为词库管理的标准动作。V1 验收：① 校正后能一键生成本书专有词条清单；② 加入前有预览，逐条或整组确认；③ 加入后下次校正对本书同类错误自动生效。

#### 2.4.3 五条易用性底线（V1 验收项，缺一不发布）

| 底线 | 验收标准（V1） |
|-|-|
| **误删词条可撤销** | 删除 / 合并 / 修改均支持撤销与操作历史；删除前展示影响范围 |
| **改错了可恢复** | 词库每次变更自动快照；提供「恢复到任意时间点」与「恢复默认词库」入口 |
| **词库文件不暴露** | 全程 GUI 列表操作，不接触底层词库文件、目录或 CSV；CSV 互转收纳在高级菜单（V1.1 开放，见 2.4.4） |
| **批量操作先预览** | 查重、合并、批量删除必须先给预览清单，确认后执行 |
| **自定义 / 内置分级** | 用户词条与内置词库分开管理；恢复默认词库不影响自定义词 |

#### 2.4.4 词库与 CSV 互转的版本归属判断：放 V1.1

技术可行性评估已评估该功能实现简单（标准库可覆盖），但归属判断的依据不在实现成本，而在**安全模型与用户分层**：

1. **绕过 GUI 安全模型**：CSV 导入等于批量改词库，天然规避「批量先预览」「误删可撤销」两条底线设计的交互路径——除非为 CSV 导入单独建设预览与撤销，否则与五条底线冲突；而单独建设等于把 V1 的词库安全工程量翻倍。
2. **现有实现未接线、未验证**：技术报告明确词库 CSV 读入函数当前未接线，其行为未经实战验证，直接 GUI 化有回归风险。
3. **V1 目标用户不需要**：V1 聚焦 B 层（自出版作者 / 网文写手），单机单用户、应用内维护词库即可；需要 CSV 批量进出的 C 层（工作室批量管库）不是 V1 服务对象。
4. **真实成本在验证而非转换**：CSV 转换本身简单，但「导出的 CSV 被外部改动后导回」的边界情况（转义、编码、字段缺失）验证成本高，V1 不值得为低频路径买单。

结论：CSV 互转放 V1.1「高级模式」，随批注闭环、手动检索等文件级维护能力一起开放（触发条件见第七章），并在 V1.1 中按五条底线同等标准建设预览与撤销。

### 2.7 进入 V1 功能的选项级清单（GUI 落点与控件形态）

本节回答一个具体问题：**进入 V1 的功能，其 GUI 必须复现入口提供的完整选项，而不是入口名。**「文本排版」入口背后是 14 个可独立开关的处理项；「书籍校正」入口背后是三种运行模式加词库组合。若 GUI 只做一个「一键校正」按钮而不暴露这些选项，V1 就把现有能力砍掉大半，只是换了个壳。以下逐功能枚举全部可执行选项与参数，并为每个选项指定 GUI 落点与控件形态。

**阅读约定**：①「控件形态」只取开关 / 单选 / 多选 / 下拉 / 输入框 / 按钮 / 对话框 / 向导页 / 只读展示九种，不自造形态；②本节只覆盖**进入 V1 的功能**，标「V1.1」的选项是该功能中不进入 V1 的那一部分（与 2.5、2.6 去向一致），列出只为说明砍掉了什么，不构成 V1 工作量；③标注「内部机制」的项 GUI 不暴露入口，由系统自动完成。

#### 2.7.1 formatting（文本排版 →「一键校正」的折叠可选项）

该命令的本质是**一串可按编号挑选的处理步骤**，原命令运行时交互选择执行哪几项。V1 必须把这串步骤完整搬进 GUI，否则用户无法只做「标点规范化」而不动大小写。按功能清点给出的实际执行顺序，逐项枚举如下。

| 序 | 处理项 | 具体行为与可调参数 | GUI 落点 | 控件形态 |
|-|-|-|-|-|
| 1 | 编码与换行符转换 | 源编码自动识别（UTF-8 / GBK / GB18030），换行统一；转换时以人话提示 | 导入书籍时自动执行 | 内部机制（提示气泡） |
| 2 | 英文大小写转换 | 含数百个固定大小写词组（带断言） | 一键校正 → 排版选项 → 「英文大小写」 | 开关 |
| 3 | 数字转换 | 阿拉伯 ↔ 中文数字互转，带防误伤表（如「国窖1573」不转） | 排版选项 → 「数字格式」 | 下拉（不转换 / 转中文 / 转阿拉伯） |
| 4 | 去中文间空格 | 清除汉字之间的多余空格 | 排版选项 → 「清理正文空格」 | 开关 |
| 5 | 按标点分行 / 还原 | 按标点标记断行，或反向合并为整段 | 排版选项 → 「断行方式」 | 单选（分行 / 还原为整段 / 不动） |
| 6 | 特殊字符转义还原 | 还原 EPUB / HTML 来源文本中的转义实体 | EPUB 导入时自动，TXT 不触发 | 内部机制 |
| 7 | 标点规范化 | 全半角、省略号、破折号统一，约 40 组正则（含引号转换） | 一键校正默认项 → 排版选项 → 「标点规范化」 | 开关（默认开） |
| 8 | 多行引号处理 | 跨行引语补行首引号 / 移除多余行首引号 | 排版选项 → 「多行引语」 | 单选（补引号 / 去引号 / 不动） |
| 9 | HTML 转 TXT | 剥离 HTML 标签转纯文本 | 导入时按来源自动判断 | 内部机制 |
| 10 | TXT 排版 | 去空行、加缩进、插入章节分隔、剥离残留标签 | 一键校正默认项 → 排版选项 → 「段落与缩进」 | 开关（默认开）+ 「缩进字符数」输入框 |
| 11 | 分级标题 | ◎ 标记转「第X部 / 卷 / 章」，最多三级 | 排版选项 → 「章节标题分级」 | 下拉（不处理 / 一级 / 两级 / 三级） |
| 12 | 书籍信息提取 | 从正文中提取书名、作者等元信息 | 导入书籍时自动，结果在「导出」页可修正 | 内部机制 + 导出页输入框 |
| 13 | 附加校对声明 | 文末追加校对声明，署名取配置中的署名值 | 排版选项 → 「校对声明」 | 开关 + 「署名」输入框（留空则不署名） |
| 14 | 中英文之间加空格 | pangu 风格，在汉字与拉丁字母 / 数字之间自动补空格 | 排版选项 → 「中英混排加空格」 | 开关 |

**入口形态**：14 项全部收进「一键校正」页的「排版规范化（可选）」折叠面板，默认只开第 7、10 两项（即 2.2 入口②所述「排版项作为可选项折叠呈现」）；用户展开后可逐项调整，配置按用户持久化、下次沿用。第 1、6、9、12 项属导入时机的自动处理，不做开关。

**原命令的一个特殊行为要在 GUI 里保住**：执行引号转换类排版操作时，原实现会同步处理对比基准且不做备份，以保证基准同步移动。V1 的等价机制是——凡改动正文的操作，快照链与替换报告基准同时推进，避免报告把已排版差异误算成本轮替换（2.2 入口⑤的替换统计准确性依赖此点）。


#### 2.7.2 书籍校正（1 号 + 2 号入口 →「一键校正」主按钮 + 高级选项）

该命令是 V1 的主干命令，它本身**有三种运行模式**，每种模式下还有词库组合与引擎选择。GUI 若只做一个「开始校正」按钮，等于默认锁死「完整流程 + 默认词库 + 默认引擎」一种组合，把另外两条路径丢掉。V1 的落点是：主按钮走默认组合，其余选项收进高级面板。

| 运行模式 | 原命令行为 | GUI 落点 | 控件形态 |
|-|-|-|-|
| 完整流程（默认） | 备份 → 预处理（排版）→ 词库批量替换 → 校验，一条龙。对应 1 号入口 | 「一键校正」主按钮，无需展开面板 | 主按钮（等价默认单选） |
| 跳过预处理 | 不做排版预处理，直接用词库校正；进入后交互选择特殊子模式。对应 2 号入口 | 高级面板 → 「运行模式」 | 单选（完整流程 / 跳过预处理），选中后展开子模式面板 |
| 临时校对表替换 | 走「临时校对表」子流程，额外产出未命中校验报告。对应 10 号入口 | V1 不设入口，由 V1.1 批注闭环接管（与 2.5、2.6 一致） | V1.1 范围，列出仅为说明砍掉的范围 |

**跳过预处理的四种特殊子模式**（选中该模式后展开）。这四种模式是 2 号入口的实质内容，属 V1 工具集的一部分，必须可被用户触达，否则「跳过预处理」这个模式本身没有意义。

| 子模式 | 行为 | GUI 落点 | 控件形态 |
|-|-|-|-|
| 严格模式 | 用严格词库组合做校正，规则更紧 | 高级面板 → 跳过预处理 → 「词库严格度」 | 单选（常规 / 严格） |
| 生僻字注音：仅注一次 | 为生僻字补充注音，全篇每个字只注第一次 | 高级面板 → 跳过预处理 → 「生僻字注音」 | 单选（不注音 / 仅注一次） |
| 生僻字注音：所有位置 | 同一生僻字每次出现都注音 | 同上 | 单选（仅注一次 / 所有位置） |

**词库组合与引擎选择**（两种模式共用）。

| 选项 | 原命令行为 | GUI 落点 | 控件形态 |
|-|-|-|-|
| 词库组合（10 组） | 运行前交互选择词库组合序号，按配置分组装配（预处理时用另一套组合） | 高级面板 → 「使用哪套词库」 | 下拉（10 组，带人话说明，默认「常规校正」） |

#### 2.7.3 文本合并（5 号入口 → 导入书籍的自动动作）

该命令按章节清单顺序抽取 EPUB 各章节文本，合并为同名 TXT，合并日志单独留档。V1 不设独立入口（2.2 入口①要求「EPUB 导入无概念暴露」），但它的**参数空间**必须以选项形式露在导入向导里。

#### 2.7.5 词条相关操作（未编号入口 → 「词库管理」一级入口）

#### 2.7.6 生成书籍专有词库（11 号入口 → 词库管理的标准动作）

该命令对比校正前后的书籍，把「本书特有且已确认的修改」沉淀为专有词条，写入该书专有的词库文件（文件名须与书名一致）。输入为校正前后两版书籍，输出为专有词库文件。2.4.2 已把它纳入 V1，本节补齐它在 GUI 上必须暴露的参数与判断点。

| 选项 / 判断点 | 依据与行为 | GUI 落点 | 控件形态 |
|-|-|-|-|
| 前置条件校验 | 须先跑过至少一轮校正，两版书籍才有差异可比（否则空结果） | 触发前自动检查，不满足则禁用按钮并说明原因 | 按钮禁用 + 提示 |
| 书名一致性 | 专有词库文件名须与书名一致 | 生成前展示将写入的文件名 | 只读展示 + 可改名输入框 |

该命令以备份基准为对照、比对当前书籍差异，把「本轮实际发生的替换」反推为替换对，写入临时校对表，并落统计报告文件。**V1 只做文件形式留存的报告，不做 GUI 呈现**（2.2 入口⑤与 2.5「替换报告 GUI 呈现 → V1.1」一致）。

## 三、V1 架构基线

### 3.1 总体架构：Python 应用层 + 替换引擎后端（已定稿：Go 默认 / Python 可选）

引擎最终方案**已定稿**：Go 引擎为默认引擎；Python 引擎（pyahocorasick greedy，已验证与 Go 逐字节等价）一并实现；设置页提供「替换引擎」可选项供用户选择，默认 Go；Go 引擎缺失或异常时自动降级到 Python 引擎的既有降级逻辑（3.3）保留。本节按此定稿展开，不再并列两方向呈现。**真实语料复测口径不变**（详见 3.4）：三部真实网文合并 37.15MB，Go 26.34 MB/s vs Python greedy 3.09 MB/s，全量倍率 2.4–5.5 倍，Python 最大单册全量 17.9 秒。

- **默认引擎 · Go 内置后端**：Go 替换引擎（strings.NewReplacer，约 130 行）作为内置后端随软件分发，应用层子进程调用；性能上限最高，代价是随包多一个可执行文件与杀软误报面（3.2 / 5.2）。用户不改设置时始终走此路径。
- **可选引擎 · Python（pyahocorasick greedy）**：greedy 全量匹配 + 贪心选路，已与 Go 逐字节等价验证；在设置页「替换引擎」中由用户主动选中；无独立引擎进程、分发更干净，代价是大书全量替换耗时进入数十秒区间（最大单册 17.9 秒）。同一实现同时承担 Go 缺失 / 异常时的自动降级路径（3.3）。
- **应用层（重写）**：Python 3.11+ / PySide6 统一 GUI；排版、引号、词库、历史、报告、错误处理全量以 Python 重写；17 个原命令行命令的能力并入界面流程，PHP 运行时整体消除。
- **引擎层（两个引擎共用的替换语义）**：不论实际运行 Go 还是 Python，替换语义与词库展开排序都以 Go 现状为准——参数顺序优先（first-wins）、失败前进 1 字符、命中后跳到匹配结束、不重叠、生产两趟；词库展开沿用既有展开算法（array_reverse + 字节长度降序），规则总量 304,256 条。Go 引擎本体作为默认引擎随包分发；Python 引擎不依赖该可执行文件。
- **禁止事项（写入代码评审门禁）**：flashtext（win_rate=0，连排关键字漏替）与 pyahocorasick iter_long（失败吞字符，99.03% 窗口）不得作为引擎实现依据。

### 3.2 Go 后端的打包分发（纳入 V1 工作量与验收）

Go 引擎以独立可执行文件形态随软件分发（与主程序同目录），应用层以子进程调用。V1 验收标准：① 解压后无需任何额外下载或配置，Go 路径开箱即用；② Go 子进程异常（被杀软隔离、启动失败）有明确检测与人话提示，不静默失败；③ 移除软件时删除整个文件夹即可，不留系统残留与孤儿进程文件。

### 3.3 降级路径（供评审）

当 Go 引擎被杀软隔离、缺失或启动失败时，自动降级到已验证**逐字节等价**的 pyahocorasick greedy 实现（全量匹配 + 贪心选路），界面明示耗时量级差异（大书约数十秒）后由用户确认执行。默认引擎是 Go；用户也可在设置页「替换引擎」中主动选中 Python 引擎走同一实现。greedy 实现同时充当引擎回归测试的语义对照基准。

### 3.4 Python 引擎：greedy 实现 + 必备进度与取消（已纳入 V1）

Python 引擎为 pyahocorasick greedy 逐字节等价实现 + 必备进度与取消。按 P0 报告最新版真实语料实测：三部真实网文（12.06MB / 1.60MB / 23.48MB）分册各测一次并拼接为 37.15MB 合并文件再测，全量口径倍率 2.4–5.5 倍；合并文件 Go 26.34 MB/s vs Python greedy 3.09 MB/s；Python 最大单册全量 17.9 秒、Go 3.23 秒。**旧口径（20MB 单本 47.79 秒、勉强可接受）基于公版繁体语料、命中密度偏高，已被真实语料复测取代，本文不再引用。**该方案**已纳入 V1**：Python 引擎与 Go 引擎一并实现，经设置页「替换引擎」切换、默认 Go，不改变 Go 的默认地位。greedy 实现当下用于三处——可选引擎本体、引擎回归的逐字节语义对照基准，以及 Go 缺失 / 异常时的降级路径（3.3）。

### 3.5 重写注意事项（写入 V1 范围与代码评审门禁）

- 6 处原运行时闭包行为必须在 Python 侧重写实现并**单独测试**，不可依赖 JSON 序列化结果；
- 严格词库的已知瑕疵（以排除标记作为键而非值）按**数据清洗**处理，不作为代码缺陷阻塞迁移；
- 迁移脚本与重写工具链必须**显式检测运行时闭包并报警**，禁止静默降级；
- 以上三条连同「禁用 flashtext / iter_long」一起作为全里程碑代码评审的固定检查项。

双口径：**易用性**——无文档帮助 10 分钟内独立完成率 ≥ 50% 且词库误操作不可恢复事件 = 0；**正确性**——回归基线集逐字节一致。二者均为发布硬门槛。

## 七、后续方向（V1.1 / V2）

### 7.1 V1.1 高级模式

**主题**：面向专业工作流开放文件级维护能力。**内容与优先级**（高 → 低）：修改前后对比视图（补 V1 的预览短板）→ 批注闭环 → 手动检索 → 重复段落检测 → CSV 互转（按 2.4.4 理由与五条底线同等标准建设）→ 多本书批量 → 替换报告 GUI → EPUB 手动解压 / 压缩入口 → 文件全局搜索编辑器（单体量最大，压轴）。**触发条件**：V1 内测独立完成率 ≥ 70%（低于 50% 重新审视交互设计与目标用户定义，50–70% 之间先做易用性补强再开高级模式）。

### 7.2 V1.2 / V2 协作与架构升级

**V1.2（协作与云）**：词库云同步、团队共享词库、在线词库市场；触发条件为「词库管理高频使用且出现跨设备 / 团队共享需求」。**V2（架构升级）**：若用户量或功能复杂度触及混合栈瓶颈，考虑核心引擎统一为单一语言。自动更新与事务式崩溃恢复随这两个版本按需纳入。

### 7.3 优先级原则

后续版本一律由**使用数据触发**而非功能完整度驱动：V1.1 看内测完成率，V1.2 看词库管理使用强度与共享需求，V2 看架构瓶颈信号。无触发信号则不开新版本。

### 7.4 V1.1 候选补充（本期新增需求与能力缺口）

除 7.1 已承诺的九项，另有一批候选需要登记进 V1.1 视野，避免被误当作 V1 未完成项。工作量单位同为「卡」（一轮可完成的独立任务量），仅「词条启用 / 禁用」为已核验口径，其余为估算，评审时可校准。

| 候选 | 级别 | 工作量 | 用户价值 | 依赖 | 建议 |
|-|-|-|-|-|-|
| 词条启用 / 禁用 | 必做 | 3 卡（核验口径） | 给词条一个开关，被禁用的不参与校正 | 无 | V1.1 第一项 |
| 按书专有词库 | 跟随 | 2 卡（估算） | 一本书一套词，不同题材互不干扰 | 依赖词条启用 / 禁用的设计 | 紧接前一项 |
| 正则规则接入 | 待定 | 10 卡（区间 9–11） | 补齐与旧版差距最大的一类能力 | 需先完成架构评估 | 评估结论出来再决策 |
| 暗色模式 / 图标 | 可选 | 3 卡（估算） | 夜间阅读体验 | 无 | 此前明确不做，需重新确认 |
| 引入数据库 | 不排期 | — | — | — | 仅备忘，不进任何排期 |

**词条启用 / 禁用（必做）**：给词条一个启用 / 禁用状态，被禁用的不参与校正。设计要点五条——① 禁用集单独存一个文件，不动出厂词库只读的底线；② 禁用键用词条内容的哈希值定位，不依赖行号或顺序；③ 词库变更识别必须把禁用集算进去，否则改了禁用状态但标记不变，断点恢复会复用旧正文；④ 界面复用已有的撤销栈，「恢复默认」与「清空禁用」是两个独立操作，不能合并；⑤ 被注释且无在用出处的词条以「禁用」状态迁入内置词库——词条可见、可自行启用、默认不参与校正；已有在用出处的注释词保持现状不动；已知的孤儿词条从误迁的在用状态改为默认禁用。四项工作分别是数据层与变更识别（含注释词条迁入）、界面、引擎过滤加回归；注释词条约 6,000 条的迁入属数据层一次性导入与核对，卡数由评审校准。

**正则规则接入（待定）**：界面与功能检查确认，三类正则规则整类尚未迁移，是当前与旧版差距**最大**的功能缺口——旧版能用正则表达无法穷举的替换，新版目前做不到。架构评估结论：自动替换路径共 68 条纯正则、0 条回调，须走独立正则通道（兼容层为现成载体），建议按 10 卡排（区间 9–11）——原 5–7 卡是「最小可用」口径，不含后置修复链（正确性阻塞项，不接即负收益）。性能实测：正则通道使 Go 引擎整本替换耗时约 +95%、Python 引擎约 +10%。是否进 V1.1 待决策；若进，启动前须在同一份样书上重测出一组可比命中数——现有三个命中数样本或口径不同，不可直接比较。

**按书专有词库（跟随）**：旧版具备按单本书单独配置排除词的能力。它与词条启用 / 禁用天然衔接——先做通用禁用，再把范围从「全局」扩展到「按书」，比直接做按书配置省一大截。

**依赖关系**：词条启用 / 禁用与正则规则接入须串行（两者都改引擎的装载层，同处代码同时动两件事冲突与回归成本都不划算）；按书专有词库依赖前者；其余候选与主链路无代码依赖，可并行或穿插。

**与 7.1 的关系**：本节候选是**插入建议**，不推翻 7.1 的九项承诺顺序。建议的排法是——V1.1 先做「词条启用 / 禁用 → 按书专有词库」这条主线（5 卡），其后按 7.1 顺序分批进入；正则规则接入是否插入由架构评估结论决定。这只是一条排法建议，不是已定排期，也不改变 7.1 已承诺的范围。
