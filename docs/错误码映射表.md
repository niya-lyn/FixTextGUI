# FixText 错误码映射表（M2-T2.4 人话错误体系）

版本：v1 · 2026-10-27
定位：全应用**唯一**的错误呈现契约。界面上的每一句错误文案都必须来自本表（或调用方显式提供的 `safe_hint`）。
配套代码：`fixtext_error_center/`（独立模块，T2.1–T2.3 / M3 各卡接线时统一 import，见第 4 节）。

---

## 1. 设计原则（对应排期 2.3 底线「不暴露技术名词 · 人话提示」）

1. **两层错误码**：T0.3 引擎层 E1xxx/E2xxx 是机器口径，面向程序分流；本表 U 码是用户口径，面向呈现。`classify.py` 负责 E 码 → U 码翻译，不另立体系。
2. **三段式文案**：每码 `title`（卡片标题，动作导向）+ `what`（发生了什么，说人话，≤2 句）+ `guidance`（下一步指引，用户能做的事）。**没有无指引的空文案**。
3. **技术细节只进日志**：traceback / 异常类名 / errno / 命令行输出只写入诊断日志（JSONL，按天一个文件，2MB 滚动保留一份），界面只呈现人话。设置页提供「打开诊断日志目录」入口。
4. **原始文件安全声明**：FixText 全程只读是既有底线，涉及处理失败的文案里如实告知「你的原始文件不受影响」。
5. **兜底永在**：未枚举异常落 `U-R00` 通用兜底 + 技术细节进日志；`classify` / `report` / `guard` 永不抛异常。

## 2. 错误码 → 人话文案全表（验收标准 2 逐类核对用）

### 导入类 U-Ixx

| 码 | 标题 | 发生了什么（what） | 下一步指引（guidance） |
| --- | --- | --- | --- |
| U-I01 | 没能读取这本书 | 找不到或读不了你选择的文件——它可能已被移动、删除，或正被其他程序占用。 | 回到原来的位置确认文件还在；如果文件在 U 盘或网盘里，先等它连接、同步完成，再重新导入一次。 |
| U-I02 | 这本书的文件损坏了 | 文件内容不完整，打不开——常见于没下载完、复制中断或存储出错。 | 换一个文件试试；如果它来自网络，建议重新下载一次再导入。 |
| U-I03 | 没法识别这本书的文字 | 书里的文字用了少见的编码方式，暂时认不出来。 | 换一个文件试试；如果确认文件是好的，可以用记事本打开后「另存为」，编码选 UTF-8，再导入。 |
| U-I04 | 这本书的格式读不了 | 这本 EPUB 的内部组织和常见格式不一样，暂时解析不了。 | 先用 Calibre 打开这本书做一次「转换」（输入和输出都选 EPUB 即可修复结构），再导入；或直接转成 TXT 导入。 |
| U-I05 | 工作数据出了点问题 | FixText 自己的中间数据对不上了。你的原始文件不受任何影响。 | 重新导入这本书再试一次；如果反复出现，打开「设置」里的诊断日志目录，把最新的日志发给支持人员。 |

### 处理类 U-Pxx

| 码 | 标题 | 发生了什么（what） | 下一步指引（guidance） |
| --- | --- | --- | --- |
| U-P01 | 校正引擎没有就位 | 负责校正的组件没有随软件一起运行——最常见的原因是杀毒软件把它拦截或隔离了。 | 在杀毒软件的隔离区找到 FixText 并选择放行/信任，然后重新解压一份完整软件，再打开试一次。 |
| U-P02 | 校正中途停了 | 处理这本书时校正组件意外停止，本次没有生成结果。你的原始文件不受影响。 | 重试一次；若仍失败，换一本书处理以确认是否这本书太大或内容特殊；持续出现请把诊断日志发给支持人员。 |
| U-P03 | 处理时间超出了上限 | 这本书处理时间过长，已经自动停止，没有留下半成品。 | 重试一次；特别大的书会需要更久，可以先拆分后分批处理；反复出现请反馈给支持人员。 |
| U-P04 | 磁盘空间不足 | 电脑磁盘写不进处理结果，本次没有完成。已写入的部分会在重试时自动覆盖。 | 清理磁盘空间后重试（建议至少留出这本书大小两倍的余量）；可以先清理回收站和「下载」文件夹。 |
| U-P05 | 没有足够的权限 | 系统不允许 FixText 读取或使用这个位置，常见于系统目录或其他账户的文件。 | 把文件复制到「文档」或「下载」文件夹再试；如果软件放在系统盘的受限目录，请把整个软件文件夹移动到桌面后重新打开。 |

### 导出类 U-Exx

| 码 | 标题 | 发生了什么（what） | 下一步指引（guidance） |
| --- | --- | --- | --- |
| U-E01 | 导出目录写不进去 | 选定的导出位置现在不可用——目录可能被删、被设为只读或没有写入权限。 | 点「浏览…」换一个导出目录（建议「文档」或桌面）再试；如果是 U 盘或移动硬盘，先解除写保护。 |
| U-E02 | 导出没有保存成功 | 导出时写入文件失败，结果没有保存成功。 | 检查磁盘剩余空间和导出目录后重试；换一个目录导出也可以。 |

### 运行类 U-Rxx

| --- | --- | --- | --- |
| U-R00 | 出了点意外 | 遇到了一个没有预料到的问题，这次操作没有完成。你的原始文件不受影响。 | 重试一次；如果再次出现，打开「设置」里的诊断日志目录，把最新的日志文件发给支持人员，我们会尽快修复。 |

## 3. 归类链：异常 → U 码（classify.py，按优先级）

1. **UserFacingError** 透传其 code（上游已判定时）；
2. 带 `.code`（形如 `E\d{4}`）的 T0.3 引擎异常 → 查 `ENGINE_CODE_MAP` 翻译（下表）；
3. **OSError 家族**按 errno + context 分流：ENOENT/EISDIR/ENOTDIR→U-I01；ENOSPC→U-P04；EACCES/EPERM/EROFS→ context=export 时 U-E01、否则 U-P05；其余 OSError 读侧 U-I01 / 写侧（export）U-E02；
4. **M1 引擎语义异常**按「模块前缀+类名」MRO 匹配（无需 import 引擎包）：
   - `epubtext.EpubStructureError` → U-I04，消息含「ZIP 结构损坏 / 不是合法的 ZIP」等再细分到 U-I02；
   - `epubtext.EpubTextError / BundleFormatError / RestoreError`、`fixtext_bookmap.PatchError` → U-I05；
   - `zipfile.BadZipFile` → U-I02；`lxml.etree.XMLSyntaxError` → U-I04；`fixtext_import.EncodingUndetectable` → U-I03；
5. `UnicodeDecodeError / UnicodeError / LookupError`（找不到编码名）→ U-I03；
6. 其余一切 → **U-R00 兜底**（含 MemoryError）。

### T0.3 引擎码 → 用户码翻译表（ENGINE_CODE_MAP）

| 引擎码 | 引擎语义 | 用户码 |
| --- | --- | --- |
| E1001 ENGINE_MISSING | 引擎文件缺失 | U-P01 |
| E1002 ENGINE_NOT_EXECUTABLE | 引擎不可执行 | U-P01 |
| E1003 ENGINE_TIMEOUT | 引擎超时 | U-P03 |
| E1004 ENGINE_FAILED | 引擎非 0 退出 / 被杀 | U-P02 |
| E1005 ENGINE_OUTPUT_UNEXPECTED | 引擎输出异常 | U-P02 |
| E1900 ENGINE_UNKNOWN | 引擎层兜底 | U-P02 |
| E2101 INPUT_MISSING | 输入缺失 | U-I01 |
| E2102 INPUT_UNREADABLE | 输入不可读 | U-I01 |
| E2201 RULES_MISSING | 词库规则缺失 | U-I05 |
| E2202 RULES_INVALID_JSON | 规则 JSON 非法 | U-I05 |
| E2203 RULES_LENGTH_MISMATCH | 规则长度不匹配 | U-I05 |
| E2204 RULES_EMPTY | 规则为空 | U-I05 |
| E2301 ARGUMENT_INVALID | 参数非法 | U-I05 |
| E2401 OUTPUT_WRITE_FAILED | 输出写失败 | U-E02 |

翻译表在 `error_codes.py::ENGINE_CODE_MAP` 维护；引擎码定义见 T0.3 的 `fixtext/engine/errors.py::EngineErrorCode`。

## 4. 接入指南（T2.1–T2.3 / M3 各卡统一接缝）

错误体系是**独立模块**，本卡不改 `src/` 下各模块页源码（避免与在跑的卡互踩）；接线由后续卡按下述统一方式 import。

### 4.1 应用启动时（main.py / host_window 初始化）

```python
import fixtext_error_center as error_center

error_center.init(log_dir=用户数据目录 / "logs")   # 诊断日志
error_center.install_app_hooks()                    # sys/threading 兜底钩子
error_center.set_dialog_host(main_window)           # 错误卡挂靠主窗口
```

### 4.2 各模块错误出口（导入 / 一键处理 / 导出 / 检查页）

```python
# A. 槽函数 / 按钮回调 —— 一行装饰，异常自动：归类→日志→错误卡，不崩溃
@error_center.guard
def on_import_clicked(self):
    ...   # 里面随意 raise，到不了界面

# B. 已判定错误 → 抛带码异常（透传，不被重归类）
raise error_center.UserFacingError("U-I03", safe_hint="《呐喊》.txt")

# C. 主动上报（长任务 worker 里 catch 后转发到 UI 线程）
resolved = error_center.report(exc, context="import", parent=self)
# resolved.title/what/guidance 全是人话，可直接 setText；traceback 只在日志

# D. 设置页「打开诊断日志目录」按钮
error_center.open_log_dir()
```

### 4.3 接线时的验收红线

- 模块内 `except` 后**不得**把 `str(exc)` / traceback 写进任何界面控件——统一走 `report`；
- 新增错误类别：先在 `error_codes.py` 加码 + `messages.py` 加三段式文案（过禁词 lint），`classify.py` 加归类规则，最后补单测；
- 界面文案 lint（`FORBIDDEN_TERMS`）与映射表完备性测试随包交付，接线卡回归时直接跑。

---

## 5. 诊断日志（技术细节的唯一去处）

- 路径：`<用户数据目录>/logs/fixtext-YYYYMMDD.log`，JSONL，一行一条；
- 字段：`time / code / title / exc_type / message / errno / engine_code / context / traceback`；
- 单文件 2MB 滚动保留 `.1` 一份；写失败静默降级（不因日志故障打断用户）；
- 界面侧入口：设置页「打开诊断日志目录」（`error_center.open_log_dir()`，经系统文件管理器打开）。
