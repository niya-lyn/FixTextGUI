### PCRE ↔ Python re 锚点语义差异（本轮核心发现）

在多行模式（`m` 修饰符）下，PCRE 与 Python `re` 的 `^` 语义存在实测差异（13 组样本逐位比对确认）：

- **`^`**：PCRE 匹配串首或任意 `\n` 之后（但**串尾 `\n` 之后不匹配**）；Python re.M 额外匹配「以 `\n` 结尾的串末位置」。翻译方案：`^` → `(?:\A|(?<=\n)(?!\Z))`。
- **`$`**：两者一致（串尾与每个 `\n` 之前），无需翻译。
- **换行约定**：PCRE 换行为 LF，`\r` 是普通字符。
- **`(?<!^)`**：语义为「当前位置不是行首」（零宽后顾断言断言的是当前位置），翻译为 `(?!(?:\A|(?<=\n)(?!\Z)))`；`(?<=^)` 对应改为前瞻形式。

该差异曾导致 Python 输出多出尾部缩进空格，是本项目最后一块不一致来源，修复后进入全量逐字节一致状态。

### 其他兼容层细节（均已与 PHP 实测核对）

- `trim()` 不裁剪 U+3000 全角空格（与 Python `str.strip` 的差异）。
- `strtr()` 最长键优先。
- `html_entity_decode()` 用 HTML 4.01 实体表且**要求分号**（Python `html.unescape` 用 HTML5 表且允许省略）。
- `strip_tags()` 的标签起始判定：`<` 后跟空白（空格/\t/\n）为字面量，跟其他任意字符（字母、数字、汉字、`.`、`-`、`>` 等）均为标签起始（PHP 8.5 实测：`strip_tags("a < b")` → `"a < b"`，`strip_tags("1<2>3")` → `"13"`）。
- `preg_replace` 替换串回引用（`$1`/`${1}`/`\1`），引用不存在的分组输出空串。

## 四、Python 侧标注扩展（非 PHP 复刻，默认关闭）

以下三块功能在 FixText PHP 源码中**不存在**，按任务要求作为独立扩展交付，并显式标注与 PHP 等价性无关：

1. **宽度库**（`fixtext_layout/width.py`）：基于 Unicode East Asian Width（W/F→2、Na/H/N→1、A 可配置默认 1、组合附标 0 列）。
2. **标点禁排**（`fixtext_layout/kinsoku.py`）：行首禁排（句读点不可居行首）与行尾禁排（开括号不可居行尾）。
3. **标点挤压**（`fixtext_layout/kinsoku.py`）：行尾连续全角可挤压标点中，最左 1 个保持全宽、其余折半。

**这三块不参与 `LayoutEngine.format()` 的默认调用路径**，因此不影响与 PHP 的逐字节等价结论。调用方式见 README（`wrap_text` / `text_width` 独立入口）。

## 六、边界与风险

- `toEncoding` 仅实现 UTF-8（任务范围内 FixText 排版路径实际只走 UTF-8）。
- `extractTextFromHtml`（epub 提取排版）选项字段保留、未实现完整流程（不在本任务验收范围）。
- PHP 端为 PHP 8.5.8 实测；若 FixText 升级依赖 PHP 版本行为（如实体表、strip_tags 判定变化），需重跑差分脚本回归。
- 差分对照的选项组合覆盖了全部排版开关的开启路径；个别极端组合（如 `addHtmlTag=1` 与 `quotationType` 同开等未出现在 FixText 前端配置中的组合）未逐一覆盖，如需可按 `tools/php_runner.php` 模式追加。
