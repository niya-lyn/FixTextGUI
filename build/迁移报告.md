## 4. strictMap 瑕疵：数据清洗明细

**规则**：`before` 数组中把 `mark` 写成了键而不是值 —— `['before' => [..., 'mark' => "{处理“悬殊”的问题}"], 'after' => "差距太大"]`。

**后果（`Map.php` 语义）**：

1. `flattenWord` 走 `foreach ($word['before'] as $before)`，键被忽略 → mark 字符串被当成一个 before 取值，生成一条**伪规则**；
2. `createWord` 仅在 `isset($word['mark'])` 时写 mark 键 → 词条级 mark 丢失（null）。

**处理**：把 `before` 数组里的 `mark` 键提升为词条级 `mark` 字段，并从 `before` 移除该键（只改数据，不改 PHP 源码，不作代码缺陷）。

本次清洗命中 **1 处**，涉及变量 **1 个**。

- `1.自定义词库.php` :: `strictMap` 第 14 条：
  - before（清洗前）：`["悬殊太大", "过于悬殊", "很悬殊", "非常悬殊", "十分悬殊", "{处理“悬殊”的问题}"]`
  - before（清洗后）：`["悬殊太大", "过于悬殊", "很悬殊", "非常悬殊", "十分悬殊"]`
  - 词条级 mark：`None` → `{处理“悬殊”的问题}`
  - 消失的伪规则：`before="{处理“悬殊”的问题}"`, `after="差距太大"`

**规则总数差异说明（如实记录，不强行凑一致）**：

- 基线（未清洗）规则数：**304,256**
- 清洗后规则数：**304,255**
- 差值：**-1**
  - 因清洗被移除的规则 ×1：`before="{处理“悬殊”的问题}"`, `after="差距太大"` —— 即上表那条伪规则

> 结论：与 P0 报告 304,256 的差异 **全部来自这一处数据清洗**，无其它未解释差异。
