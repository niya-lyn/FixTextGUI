# T0.4 回归基线集 · 基线方法论

## 一、基线固化对象

本基线集固化的是 **上游 FixText 的「词库 → 替换」行为**，即：给定一套语料与一套规则，替换引擎产出什么输出、执行多少次替换。它是后续词库迁移（T0.2）、Go 引擎集成（T0.3）以及 Python 重写工作的**行为回归锚点**——任何一次改动之后，都可以用一键脚本重放替换并与冻结输出比对。

固化内容：

| 项 | 内容 | 位置 |
|---|---|---|
| 语料 | 15 个文件（12 繁体公版书 + 3 真实简体小说截取） | `corpus/` |
| 规则 | 304,255 条替换规则（before/after 数组 + meta，T0.2 清洗后口径） | `rules/` |
| Go 基线输出 | 上游 `replace_by_go.go` 原样编译后对语料的校正后输出 | `expected/go/` |
| PHP 基线输出 | 复刻上游 `TextFixer::replaceByPHP` 降级语义的输出 | `expected/php/` |
| 替换计数 | 每个语料的替换次数 / 命中规则数 / 每轮命中数 / Top 规则 | `manifest/baseline_manifest.json` |
| 重跑脚本 | 一键重跑比对（含命中计数重放） | `scripts/run_baseline.py` |

## 二、规则集：来源与口径

### 2.1 规则集定义

- **全量口径**：上游 `src/maps/` 下 8 个词库文件中的全部 19 个词条型 `*Map` 变量合并（含重复条目），与 P0 验证报告定稿口径一致（`rules_meta.json` 的 `per_var` 记录每个变量的条数）。
- 共 **304,255 条规则**，其中 `before` 唯一值 **243,535 个**；存在 **972 个冲突重复键**（同一 `before` 对应多个 `after`，涉及 2,026 条规则）。`before` 的 UTF-8 字节长度范围 3–73。
- 规则数组顺序为上游 Go 语义：`array_reverse`（后设置的词条优先级更高）后按 `strlen` 字节长度稳定降序（较长词条先匹配）。

### 2.2 排除项说明（与生产配置的差异）

- 生产默认配置（`useMapsConfig[0]`）只用 4 个词库变量（punctuationMap / normalMap / cjkRecoverMap / customNormalMap）；本基线按 P0 定稿采用**全量 19 变量口径**，覆盖面更大。做生产子集回归时，可从 `rules_meta.json` 的 `per_var` 按变量名筛出子集规则。
- 基线不含 `excludedWords` 排除（词库的排除表为空，已用上游真实代码验证无影响）、不含正则替换（regexMap 属正则通道，不在本卡范围）与 postFix 二次流程。

### 2.3 规则集来源验证（强溯源）

`rules/before.json`、`rules/after.json` 并非手造：`scripts/verify_upstream_equivalence.php` 会用**上游真实代码** `App\Service\Map::flattenMaps`（含 Go 语义的逆序 + 长度排序）对全量词库重放展开，并与包内规则数组逐元素比对。首次自验结果：304,256 条**逐元素一致**（见 `03_自验记录.md`）——该次验证的对象是上游**未清洗**词库，条数为 304,256；本包当前规则集为 T0.2 清洗后的 304,255 条，见下方 §2.4。

- `rules/before.json` sha256：`e961f82e3cbb41499b41301e04e7a7df7b11e189060064b6edd5af8e881e2c26`
- `rules/after.json` sha256：`7dd53ae6fd7770c2362b0a7d893ecf03bc5bba7062f9a0cd2bb07797a76a6131`
- 以上为 304,255 口径值；历史 304,256 口径为 `932271d6e483d504…` / `b8cefff85f464283…`，见 `manifest/baseline_manifest.json` 与 `reports/重冻结对比报告.md`。

## 三、引擎语义：两个后端如何对齐

### 3.1 生产链路（上游源码事实）

`TextFixer::doReplace`（src/app/Service/TextFixer.php:313）按 `singleReplace` 配置决定 `replaceCount`（默认配置为 false → **替换执行 2 轮**），然后三选一：

1. **Go 主路径**（`REPLACE_BY_GO=true` 且 Go 可执行文件存在，生产默认）：写临时文件后调 `replace_by_go`（`strings.NewReplacer`）执行 2 轮；
2. **PHP 降级路径**（Go 失败时，`$shouldReverse=true`）：`array_reverse` 后 `array_combine`，`strtr` 执行 2 轮；
3. **PHP 直连路径**（`REPLACE_BY_GO=false` 时，`$shouldReverse=false`）：词库**不逆序、不按长度排序**，直接 `array_combine` + `strtr` 2 轮。

### 3.2 三条路径为何结果一致

- **Go**（`strings.NewReplacer`）：trie 匹配，**最长匹配优先**，重复 `before` 键以**先写入者**生效；
- **PHP `strtr`（数组形式）**：同样**最长匹配优先**；`array_combine` 对重复键取**后出现者**。降级路径先 `array_reverse`，使「后出现者」恰好等于 Go 的「先写入者」；
- **直连路径**：`strtr` 自带最长匹配优先，无需长度排序；对重复键直接取原始顺序的后者，与上面二者结论一致。

**等长不同键不会冲突**（同一位置能匹配的两个等长键必相同），所以顺序差异只剩重复键一种来源；三条路径对重复键的最终取值相同，故输出逐字节一致。

### 3.3 等价性验证（全语料实测）

| 验证 | 内容 | 结果 |
|---|---|---|
| 上游 Go vs 包内 PHP 后端 | 15 个语料全部逐字节一致 | 通过 |
| 上游 `replaceByPHP`（反射调用真实代码）vs 包内 `expected/php`、`expected/go` | 样本逐字节一致 | 通过 |
| 上游直连配置（`REPLACE_BY_GO=false`，真实 `flattenMaps($merged, false)`）vs `expected/go` | **15 个语料全部逐字节一致** | 通过 |
| 计数重放工具 vs 上游 Go 引擎输出 | 15 个语料全部逐字节一致 | 通过 |

即：**同一套规则在三条生产执行路径下的输出完全一致**。这对后续重写是重要前提——只需对齐一条路径的语义，三条路径都被基线覆盖。该结论在 304,256 与 304,255 两个口径下均成立（见 §2.4）。

## 四、替换计数口径

上游 Go 工具自身只打印「共执行 N 次替换」（N 为轮数，非命中数），不足以回归。本基线的计数由 `scripts/go/count_hits`（基线度量工具，**非新引擎**）产生：

- 与上游引擎完全相同的匹配语义（最长匹配、重复键先出现者生效、非重叠从左到右）重放替换；
- 其替换输出被强制要求与上游 Go 引擎**逐字节一致**（每次重跑都会交叉校验），证明计数描述的正是引擎行为；
- 计数指标：`replacements`（两轮累计命中次数）、`distinct_rules`（命中过的不同规则数）、`hits_per_pass`（每轮命中数，可见第二轮明显少于第一轮，符合「二次替换保证隐晦关联词条」的设计意图）、`top_rules`（Top 24 命中规则）。

## 五、冻结与比对方式

- **冻结**：`python scripts/run_baseline.py --build` 产出 `expected/go/`、`expected/php/`、`manifest/baseline_manifest.json`；
- **比对**：`python scripts/run_baseline.py`（默认模式）在临时目录重放两个引擎，按 sha256 与冻结输出比对，同时校验语料完整性、PHP==Go 一致性、计数重放一致性与替换计数；
- 退出码：0 = 全部一致；1 = 存在不一致（CI 视为失败）。
- 环境要求：python3（仅标准库）、php CLI；go 工具链（缺失时使用随包预编译二进制，仅限 linux/amd64）。

## 六、CI 集成（T0.1 骨架）

按 T0.1 骨架 `scripts/ci.py` 的 STAGES/RUNNERS 结构新增 `baseline` 环节：

- `scripts/ci.py`：`STAGES = ("lint", "format-check", "gates", "tests", "baseline")`，新增 `stage_baseline()`，缺 php/go 时按 **SKIP**（非失败）处理；
- `scripts/ci_baseline.py`：环节包装器，调用 `baseline/scripts/run_baseline.py`，退出码 77 = SKIP；
- `.github/workflows/ci.yml`：矩阵位照常跑全量（Windows 矩阵位自动 SKIP baseline），另加 `baseline` 专用 job（ubuntu-latest 自带 php/go，强制执行，不接受 SKIP）并上传比对结果 artifact。

补丁文件与统一 diff 见包内 `T01_patch/`。

## 七、口径变更记录（304,256 → 304,255）

本包是 **M1-T1.0 重冻结**版本：按排期文档附录 C 第五条裁定，V1 唯一生产基准为 T0.2 清洗后的 **304,255** 条词库，T0.4 交付时的 304,256 条口径仅作历史对照保留。

| 项 | T0.4 交付（历史） | 本包（M1-T1.0 生产基准） |
|---|---|---|
| 规则条数 | 304,256 | **304,255** |
| `before` 唯一值 | 243,536 | **243,535** |
| 冲突重复键 | 972 个 / 2,026 条 | 972 个 / 2,026 条（不变） |
| 总替换次数 | 1,666,476 | **1,666,476**（不变） |
| 命中规则并集 | 10,898 | **10,898**（不变） |
| Go / PHP 输出 | 15+15 个文件 | **与新口径逐字节相同** |

**变更内容**：只替换 `rules/` 下三个文件为 T0.2 `build/dictionary/rules/` 的产物；语料、引擎脚本、预编译二进制、CI 补丁均沿用 T0.4 原件。

**唯一规则差异**：T0.2 清洗移除了 strictMap 第 14 条误把 `mark` 写成键而产生的伪规则：
`before` = `{处理“悬殊”的问题}`，`after` = `差距太大`。

**差异为何不改变输出**：该串在 15 个语料（23,328,299 字节）中零命中——完整串命中 0 次、前缀片段 `{处理` 命中 0 次；命中规则并集新旧两侧完全相等（10,898 条，差集均为空）。因此重冻结后 15 个语料的 Go/PHP 输出、每文件替换计数、每轮命中数全部与旧基线逐字节一致。

**验证留痕**：`reports/重冻结对比报告.md`（结论与逐文件表）、`reports/rule_diff.json`（规则差异逐条）、`reports/pseudo_rule_hit_check.json`（伪规则语料命中检索）、`reports/ab_result.json`（仅换规则集的 A/B 对拍）、`reports/build_304255.json` 与 `reports/check_304255.json`（冻结与复测原始结果）。
