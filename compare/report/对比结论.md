# T1.6 PHP↔Python 对比结论

日期：2026-10-26 ｜ 方法：以真实 PHP（php 8.5 CLI，与 T0.2 迁移脚本同一环境）跑 `FixText/src`
原管线探针（`php_note_harness.php`，继承 `NoteParser`，导出三阶段 JSON），与 Python 重实现
（`py_note_parser.py` + `note_brand_processors.py`）逐字段深比对。三阶段：

1. `stage1_raw`：`extractMatches` 原始匹配行（PREG_SET_ORDER 全部分组）
2. `stage2_after_processor`：brand 闭包处理后
3. `stage3_final`：`cleanMatches` 清洗后

> 大于 64KB 的输入按「行数 + sha256 指纹」比对（`run_compare.py` 的 slim 逻辑），指纹对整段
> 规范化 JSON 计算，逐字节敏感。

## 9 处相异的逐条说明

相异文件全部为 `calibre__*` 混合语料（真实语料全文 + 附加 calibre 批注块），且全部 ≥1.6MB：

| 文件 | 大小 | PHP | Python |
| --- | --- | --- | --- |
| calibre__novel_guimie_full.txt | 1.60MB | 未找到匹配的批注内容 | calibre，2 行匹配 |
| calibre__pg23863_水滸傳.txt | 1.60MB | 同上 | 同上 |
| calibre__pg23910_封神演義.txt | 1.80MB | 同上 | 同上 |
| calibre__pg23950_三國志演義.txt | 1.82MB | 同上 | 同上 |
| calibre__pg23962_西遊記.txt | 2.22MB | 同上 | 同上 |
| calibre__pg24226_史記.txt | 1.93MB | 同上 | 同上 |
| calibre__pg24230_今古奇觀.txt | 2.85MB | 同上 | 同上 |
| calibre__pg24264_紅樓夢.txt | 2.62MB | 同上 | 同上 |
| calibre__pg52200_金瓶梅.txt | 2.27MB | 同上 | 同上 |

而 ≤1.45MB 的 6 个 calibre 混合语料（435KB / 502KB / 831KB / 1.15MB / 1.45MB / 255KB）双方均
匹配 calibre 且**三阶段 sha256 完全一致**——即「PHP 引擎能跑完 ⇒ 结果逐字节等价」。

### 根因（已实证，compare/probe_backtrack.php 可复现）

对最小相异文件 `calibre__novel_guimie_full.txt` 直接跑 PHP 探针：

```
backtrack_limit=1000000
calibre preg_match_all return=false last_error=Backtrack limit exhausted
```

calibre 匹配模式为 `^(.*?)(?:\n[0-9]{4}/[0-9]{1,2}/[0-9]{1,2}.*?\n(.*?))?\n───`（懒匹配）。
混合语料把批注块放在全书之尾，`^` 锚在每个行起点都要懒惰扩展扫到文件末尾才能判定失败，
总回溯量随文本规模超线性增长；文本 ≥1.6MB 时超过 PCRE 默认
`pcre.backtrack_limit = 1000000`，**整个 `preg_match_all` 中止并返回 false**。
`NoteParser::extractMatches` 将其视为无匹配（`if (preg_match_all(...))` 的 falsy 分支），
遍历完后续模式均不命中，最终抛「未找到匹配的批注内容」——**calibre 闭包从未被调用**。

Python `re` 引擎没有回溯上限，同一模式正常完成匹配。

### 定性

- 这 9 处差异是**正则引擎资源限制差异**（PCRE backtrack_limit vs Python re 无上限），
  不是 3 处闭包（本卡交付物）的逻辑差异；差异场景下 PHP 闭包零执行。
- 从能力角度，Python 侧严格更强：PHP 因引擎限制解析失败的大文件，Python 能正常产出。
  真实 calibre 导出（批注块自身即文件主体、分组1 跨度小）不会触发该限制；本混合语料把
  批注块置于 MB 级全书之后，属于构造出的边界压测场景。
- 若产品侧要求严格复刻 PHP 的「超限即失败」行为，需在调用层按文本长度/回溯预算做
  前置判断（Python re 无法精确复刻 PCRE 的回溯计数），本卡按验收标准以逐条说明结案。

## 闭包等价性证据汇总

1. **10/10 fixtures** 三阶段逐字段深比对全等（含各品牌边界用例：moonreader 嵌套括号/
   无空格括号/跨行分组、calibre 行内 `#`/无空格 `#`/BOM、weread 缺「原文：」→ `''`/纯划线
   保分组2/整体倒序优先级）。
2. **moonreader 15/15、weread 15/15 混合语料**三阶段 sha256 全等——闭包在真实语料文本上执行。
3. **calibre 6/6（PHP 可完成的范围内）**三阶段 sha256 全等。
4. **21 条单元测试**（`pytest`，不依赖 PHP）覆盖三闭包各分支与 PHP 语义边界（缺键自动扩展、
   trim 字符集、`?? ''` 合并、引用重绑定等），21 passed。
