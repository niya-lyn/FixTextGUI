# 比对视图说明

一、比对内容

这里比较的是“文件列表”中选定的 books 内文件，和 booksBak 的上一版本同名备份文件之间的差异。

 • 支持通过顶部的“上下文行数”按钮调整差异项的上下文内容，目前设置强制显示至少 1 行的上下文，
   避免在替换时因缺少上下文而出错。

 • 不支持分别设置“上文行数”和“下文行数”，实际以“下文行数”的数字为准。

 • 支持以右键菜单的【扩展/预览匹配项……】，实时预览某个不确定差异项的上下文，可直接修改并保存。
   也可以考虑多开一个窗口分屏显示，在另一个窗口中实时检索上下文。

——————

二、前置操作要求

比对前，请先通过脚本的各类编辑功能进行修改和保存，生成对应的 booksBak 旧版本文件后才能比对。

如果比对时出现“生成 patch 文件... 发生未知错误...”的报错，请将 src/tools 文件夹中的 msys-1.0.dll，

复制到 C:\Windows\SysWOW64（如果电脑中没有，可无视）以及 C:\Windows\System32（如果电脑中没有，可无视）这两个文件夹后再执行。

——————

三、内容差异标识规则

1. 【灰色背景】的文字表示“旧内容”，会与【黄色背景】的“新内容”成对出现，表示“被更改”。

    示例：这里的是<［o:旧内容］><［n:新内容］>，只有黄色部分的文字会被实际保存到文件中。

2. 【红色背景】的文字表示“被删除的内容”。

    示例：我是<［d:被删除的内容］>，在新文件中其实已经消失了。

3. 【绿色背景】的文字表示“新增的内容”。

    示例：我是<［a:新增的内容］>。

PS：建议尝试切换到深色主题来查看差异，对比度更高，更易辨识，浅色的配色调不太明白了……

——————

四、建议新开窗口查看比对结果

请注意，点击比对后，当前文本框内的搜索结果会被替换为差异项的内容。

建议再次执行【文件全局搜索.bat】，新开一个窗口，分屏显示。

让一个窗口负责正常的搜索替换，另一个负责查看差异结果，可以实时确认上下文和同步当前的修改。

——————

五、差异还原操作

在差异项处【悬停】鼠标，或【框选】多处差异项，使用快捷键【F5】或【Alt+V】，可进行还原操作。
（注意：当有“选中内容”时不会触发悬停弹窗。）

还原示例（可以在这里尝试点击还原）：

    【我是<［o:旧内容］><［n:新内容］>】，会被改为【我是<［n:旧内容］>】，还原“旧内容”，删除灰色背景的文字。

    【我是<［a:新增的内容］>】，会还原为【我是<［d:新增的内容］>】，表示把新增的内容去掉。
    （在上面那一行点击“采用”会更新内容，按键盘【F5】，则会还原成删除。）

    【我是<［d:被删除的内容］>】，会还原为【我是<［a:被删除的内容］>】，表示把被删掉的内容补回来。
    （按 Enter 会直接“采用”，万一需要在编辑框换行，可以用【Shift+Enter】。）

除了还原差异项，也可以把上下文中一些明显的错误也顺手改掉，然后点击保存就能覆盖旧文件。

——————

六、标签格式与编辑注意事项

为了更醒目，差异项都会以“空格”和“标签”包裹，可以无视前后的空格和标签，只关注有文字内容的部分。

示例（外层标签的字号很小，几乎不可见，但在文本框中是实际存在的）：

    <[a:新增的内容]> <[d:删除的内容]> <[o:旧内容]> <[n:新内容]>

1. 目前改写了光标的定位行为，会在点击差异项时弹出对应的编辑框。

   也可以用鼠标选中多行后，使用快捷键【F5】或【Alt+V】来进行批量还原。

2. 也改写了编辑器的复制行为，使用【Ctrl+C】的默认快捷键时，选区里的 <[a:]> 等等标签会被移除，然后才写入剪贴板。

    要是想使用“搜索文本框”的功能来统一替换当前文本框内的部分差异项，

    复制出来的去掉标签后的内容，**和文本框里的实际内容是对不上的**，无法顺利搜索替换。

    可以改用【Ctrl+Shift+C】来复制，会完整保留选中文字内的标签，

    然后“搜索文本框”时才能正常进行匹配计数和统一替换（最好是在另一个窗口操作）。

3. 如果觉得同时显示旧内容会干扰判断，可以勾选“隐藏灰色背景的【旧内容】”。

    比如：【我是<［o:旧内容］><［n:新内容］>】。

    很多时候只看【<［n:新内容］>】就可以猜到原来的内容是什么了（脚本词库相对固定），要是每次都同时显示两个，反而容易看错。

    勾选后，只显示：【我是<［n:新内容］>】。

    当对某处修改不确定时，将鼠标悬停在黄色部分的文字上方，可以显示出本来的【<［o:旧内容］>】，然后点击“采用”还原。

    或者可以框选多个包含【<［n:新内容］>】的行，按【F5】或【Alt+V】批量还原。

4. 在比对时，可设置“将差异处的前后 n 个字符视为同一差异块”。

    值越小，差异定位越精确；值越大，则展示出来的差异块越大。

    **举例说明：**

    假设原文是 `aaa。`，被修改为 `aab。`。

    在默认值 2 的情况下，看到的会是【aa<［o:a。］><［n:b。］>】，会附带其后并未改动的句号（位于行末时）。

    如果调整为 0，看到的会是【aa<［o:a］><［n:b］>。】，精确到每一个差异字符，

    ---

    假设原文是 `云满东楼`，被修改为 `月满西楼`。

    在默认值 2 的情况下，看到的会是【<［o:云满东楼］><［n:月满西楼］>】，会将附近的差异字符连到一起。

    如果调整为 0，看到的会是【<［o:云］><［n:月］>满<［o:东］><［n:西］>楼】，精确到每一个差异字符。

    ---

    如果想批量替换一些名词（善用【Ctrl+Shift+C】），又不想被位于行末的一些标点干扰，可尝试调整为 0。

    这时推荐勾选“隐藏灰色背景的【旧内容】”。

七、减少重复差异项和保存相关

有时候也推荐到别的编辑器里改动 booksBak 中的文件，把部分重复的差异项改成和 books 里的版本一致。

或者在比对时交换方向为【→ booksBak】，会显示以 booksBak 为主体的差异项，

可使用【F5】把内容改成和 books 版本一致，或利用“搜索文本框”批量替换（善用【Ctrl+Shift+C】）。

然后重新生成比对视图，能减少很多需要查看的地方。

    另外，也可以试用右键菜单中的【将差异项同步到 booksBak】，选中多个差异项后按【F6】，
    将一些“已确认没有问题的差异项”同步到 booksBak，在文本框中会马上让选中项消失。
    在下次检查，重新生成比对视图的时候就不会重复出现，提升二次检查的效率。

当选择的方向是【→ books】，文本框中所有的改动都会保存到 books 里，等于是 BC 里 books 所在的那一侧。

如果方向是【→ booksBak】，则所有的改动会保存到 booksBak，也就是 BC 里 booksBak 所在的那一侧。

只有 <［n:新内容］> 和 <［a:新增的内容］> 这两种颜色的文字会被保存，可将灰色和红色的文字视为不存在。
